## 行为

1. 生成页以周一至周日的多选按钮替代“每周天数”滑块；单次时长滑块保留。天数由选择数量自动计算。
2. 首次进入仍根据档案生成初始预览，再以实际预览星期回填选中状态；不在前端另建一套默认星期映射。
3. 选择星期或修改时长不立即请求、不修改活动计划、不清空旧预览或手动调整。
4. 有未应用的星期／时长变更时，明确提示下方是旧预览，并禁用保存。点击“按新节奏重新编排”才生成新预览，按钮旁说明会替换手动调整。
5. 至少选择一天；空选不能编排或保存。相同天数但不同星期也必须重新编排。
6. 请求失败保留所选星期及原预览，可显式重试。返回星期或时长与请求不符时拒绝替换，避免新前端连接旧后端时悄悄使用固定排期。
7. 编排与保存共用同步操作锁，避免重复点击、编排期间保存旧计划或同时修改输入。
8. “仅保存计划”和“保存并开始推荐训练”保留；首练仍用现有今天／最近下一个计划日逻辑。已有活动计划仍必须通过编辑器和 Proposal 修改，不能用生成入口覆盖。

## 接口

- `POST /workouts/plans/personalized/preview` 增加可选 `training_days`。
- `POST /workouts/plans/personalized/confirm` 增加可选 `training_days`。
- 值为 1—7 的严格整数列表，长度 1—7，不重复，服务端排序；拒绝布尔、字符串、小数、越界或空列表。
- 明确星期时，生成频率由列表长度决定；同时传入 `days_per_week` 时必须一致。
- 确认时，所选星期、频率和动作实际星期必须完全一致；不一致在请求校验阶段拒绝，不产生部分写入。
- 旧客户端省略字段或传 null 时，继续沿用原有档案频率与默认排期。响应主体、持久化动作的 `day_of_week` 与通用确认流程不重建。
- 未将选择写回个人档案或改变其他计划。

## 2026-09-09 核心功能真机验收

1. 选择周二／周四／周日，自动显示每周 3 天，重新编排的预览仅包含所选训练日：用户反馈“第一组通过”。
2. 同天数换星期、仅选周日、空选保护及恢复选择：用户反馈“第二组通过”。
3. 手动调整后切换星期保留旧预览，提示重新编排及替换范围，显式编排后应用新星期：用户反馈“第三组通过”。
4. 断网编排失败保留所选星期和旧预览，恢复同一 Wi-Fi 后显式重试成功，无需重新登录：用户反馈“第四组通过”。
5. 保存并开始推荐训练，推荐日与所选星期对应，进入动作一致，返回计划列表仍为所选三天且能找回进行中训练：用户反馈“第五组通过”。
