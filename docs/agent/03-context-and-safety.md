# 上下文装配与健康安全

## 上下文装配协议

ContextAssembler 只装配完成当前子任务所需的最小数据：

- 身份：内部 `user_id`，不把 AppSecret、令牌、OpenID 等秘密交给模型。
- 用户：与意图相关的资料字段及其更新时间。
- 健康：仅提供与本轮训练安全相关的筛查摘要。
- 训练：活动计划、下一练、进行中训练、有限条数的历史和聚合进度。
- 对话：最近消息窗口、会话摘要、未完成意图和待确认提案。
- 来源：每段上下文带类型、时间和可信级别，便于冲突处理。

工具返回内容有大小和条数上限；详细历史通过工具按需查询，不一次塞入 Prompt。

当查询必须澄清时，会话保存原始消息、消解结果、子任务、缺失槽位和澄清问题。下一条消息先判断是填槽、取消还是独立新问题：单槽有效回答恢复原任务；无效回答继续澄清；明确的新意图不会被旧状态劫持。

## System Prompt 约束

- 明确 Agent 身份、能力边界、可用工具和停止条件。
- 不伪造用户数据、工具结果或执行成功状态。
- 业务事实必须来自工具；一般知识回答可以不调用工具。
- 提案必须说明依据、关键变化和是否需要用户确认。
- 无法确认的事实应表达不确定性或请求澄清。

## 健康安全策略

- 胸痛、呼吸困难、晕厥、严重急性疼痛等红旗症状优先建议停止训练并及时寻求专业医疗帮助。
- 明显疼痛时不建议加量；优先停止冲突动作、降量或给出安全替代提案。
- 不进行诊断、处方、康复治疗承诺或超出产品能力的医疗判断。
- 安全检查分别发生在意图输入、工具调用前和最终输出前；高风险结果不能被普通生成内容覆盖。
- 健康安全阻断、替换和降级原因写入审计记录。
