# 阶段 5：完整对话理解层

实施日期：2026-08-20。

## 目标

在工具路由之前增加可审计的对话理解协议，解决短句承接、指代、省略、多目标拆解和多轮澄清，同时不把意图固定成工具工作流。

## 运行链路

```text
原始消息 + 最近对话 + 待澄清状态
  -> 查询重写与指代消解
  -> 主意图与必要扩展意图
  -> 动态语义子任务
  -> 缺失槽位与澄清门
  -> 最多 4 个候选工具白名单
  -> LangChain Agent 自主调用与停止
```

结构化结果保存 `resolved_query`、`references`、`expanded_intents`、`subtasks`、`missing_slots`、`clarification_question`、风险和置信度。主模型同时收到用户原话、消解后查询和语义目标，但只能看到路由白名单中的工具。

## 澄清状态

- 必须澄清时不调用业务工具，将理解快照保存到 `agent_conversations.pending_clarification`。
- 单一槽位回答通过类型相关的最小校验后合并回原查询并恢复执行。
- “取消、算了、不用了”清除原任务；显式新意图绕过旧澄清状态。
- 多槽位或无效回答在模型不可用时继续询问，不猜测、不开放工具。

## 安全边界

- 最近对话和待澄清 JSON 都视为不可信上下文，仅用于消解。
- 工具白名单仍由服务端枚举生成，未知工具无法由模型添加。
- 高风险健康信号覆盖上下文与模型分类，并在工具调用前阻断。
- 规则降级保留明确承接和单槽填充；复杂指代失败时退回安全澄清。

## 验证

- 规则评测 17 项：主意图、风险、澄清准确率和允许工具召回均为 100%，禁止工具泄漏为 0。
- 真实 DeepSeek 评测 19 项达到相同门禁；16 项使用模型，3 项使用确定性承接/填槽规则。
- 后端完整回归 176 项通过。
