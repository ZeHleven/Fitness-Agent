# 意图解析与工具路由

## IntentResolver 输出

结构化输出至少包含：

- `resolved_query`：完成指代、时间范围和省略补全后的独立查询。
- `references`：原表达、解析值、类型和上下文来源。
- `primary_intent`：主意图。
- `expanded_intents`：合理拓展但不改变用户目标的关联意图。
- `subtasks`：可独立完成的子任务及依赖关系。
- `missing_slots`：完成任务所缺的必要信息。
- `clarification_required`：是否必须先澄清。
- `clarification_question`：单一、具体且可直接回答的澄清问题。
- `risk_level`：`low`、`medium` 或 `high`。
- `confidence`：0 到 1。

只有缺失信息会实质改变结果或触发高风险行为时才澄清。能用现有用户资料或只读工具安全补齐的信息，不重复询问用户。

`subtasks` 是动态语义目标，不绑定固定工具或调用顺序。它会与消解后的查询一起进入 Agent 执行上下文；ToolRouter 只据此生成候选白名单，仍由 Agent 决定调用、顺序和停止条件。

## ToolRouter

ToolRouter 根据解析结果、风险等级、功能开关和用户权限生成本轮工具白名单。它不预先编排固定调用步骤，也不强制模型调用工具。

规则：

- 默认拒绝未进入白名单的工具。
- 工具描述使用互斥、具体的适用场景，避免语义重叠。
- 路由和工具参数均使用结构化输出校验。
- 对容易混淆的工具增加正例、反例和 few-shot。
- 第一版白名单只能包含查询类和提案类工具。
- 单轮最多开放 4 个候选工具；超出时按主意图和扩展意图顺序截断。
- 写工具即便已经实现，也必须同时通过功能开关、权限、确认状态和幂等校验才能暴露。
