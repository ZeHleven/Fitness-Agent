# 阶段 4：Agent 生产可靠性收尾

实施日期：2026-08-20。

## 触发原因

真实微信环境确认 `cloud.callContainer` 在 15 秒终止同步请求。Agent 模型与工具循环通常可在数秒完成，但冷启动、网络波动或模型延迟会越过该边界，因此仅调大前端 timeout 不能形成可靠生产协议。

## 异步运行协议

小程序不再同步等待 `/agent/chat`：

1. 生成并本地持久化 `client_request_id`。
2. `POST /api/v1/agent/runs` 在一次短事务内保存会话、run 和用户消息，随后返回 `202`。
3. 小程序按响应建议间隔轮询 `GET /api/v1/agent/runs/{run_id}`。
4. `completed` 返回回答与卡片；`failed` 返回稳定、可展示且不泄密的错误说明。
5. 页面退出、响应丢失或令牌刷新后，客户端使用同一请求 ID 恢复；服务端返回原 run，不重复写消息。

`POST /api/v1/agent/chat` 暂时保留为兼容接口，但生产小程序不再调用。

## 持久化 worker

Alembic `0013` 为 `agent_runs` 增加：

- 用户级幂等键和唯一约束。
- 排队时间、处理开始时间、租约到期时间和 worker 尝试次数。
- `queued/running/completed/failed` 生命周期。

每个 FastAPI 进程运行轻量 worker。worker 使用 PostgreSQL `FOR UPDATE SKIP LOCKED` 领取任务，多进程或多实例不会同时执行同一 run。执行中的容器异常退出后，租约过期任务可被其他 worker 接管；超过最大尝试次数后停止重试。

Alembic `0014` 增加“同一会话最多一个 `running` run”的数据库级部分唯一索引。即使用户从多台设备同时提交，同一会话仍按顺序处理，避免后发问题绕过前一轮上下文。

## 客户端恢复

- 待处理请求写入微信本地存储，包含请求 ID、消息、会话 ID 和已知 run ID。
- 提交响应丢失时，以相同请求 ID重新提交并找回原任务。
- 页面重进自动恢复轮询；等待超过三分钟时停止前台轮询，但保留恢复信息。
- 用户可明确放弃本页等待并开启新会话；后台任务不会因此重复执行或修改训练数据。
- 退出账号同步清除会话 ID和待处理请求，防止换号串会话。

## 启动与健康检查

- `/health` 只验证进程存活。
- `/ready` 验证数据库可用，并公开 worker 是否启用。
- `/__tcb_probe__` 返回 200，兼容腾讯云内部探测。
- 动作和食物种子导入从 Web 容器冷启动移至 Docker Compose 一次性 `bootstrap` 服务。
- 云托管首次应用新迁移时使用 `RUN_DB_MIGRATIONS_ON_STARTUP=true`；确认迁移到 `0014` 后，新版本设为 `false`，避免后续冷启动执行迁移检查。

## 验证结果

- 异步定向测试覆盖幂等提交、冲突拒绝、状态轮询、用户隔离和租约接管。
- 后端完整回归：168 项通过（包含会话承接与上下文工具路由用例）。
- 微信小程序 TypeScript 类型检查通过，生产构建通过。
- 真实本地 HTTP 闭环：提交接口 23ms 返回 `queued`，worker 单次领取后完成真实 DeepSeek 回答，最终状态 `completed`。
