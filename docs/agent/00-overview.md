# Fitness Agent 架构冻结说明

状态：阶段 0 冻结，2026-08-19。

## 产品边界

第一版是一个面向健身场景的对话 Agent。用户用自然语言提出问题或目标，Agent 可以检索用户资料、健康筛查、训练计划、训练执行记录、历史和进度，并给出可解释的计划或调整提案。

第一版保留写操作的完整架构，但运行时只向模型开放查询工具和提案工具。开始训练、记录训练组、完成训练、确认计划等真实写操作默认不暴露；通过验收后，再逐个启用带明确确认的执行工具。

## 核心链路

```text
用户消息
  -> IntentResolver（拓展、拆解、澄清）
  -> ToolRouter（按意图生成工具白名单）
  -> ContextAssembler（最小必要上下文）
  -> LangChain Agent（模型决策和工具调用）
  -> Safety/Policy Guard（输入、调用前、输出三层检查）
  -> 文本或卡片响应
```

这不是把固定场景绑定到固定流程。路由只限制候选工具，模型仍根据当前消息、上下文和工具结果决定是否调用、调用顺序以及何时停止。

## 技术选择

- 客户端：微信小程序（Taro + React + TypeScript）；Flutter 暂缓。
- 业务 API：现有 FastAPI，继续作为训练业务的唯一事实来源。
- Agent 编排：LangChain `create_agent`，保持薄封装，避免业务规则进入 Prompt。
- 主模型：DeepSeek V4 的 OpenAI 兼容接口；模型名由配置注入，不写死在领域代码中。
- 数据：PostgreSQL；短期会话状态与长期记忆分开持久化。
- 展示：简单问答使用纯文本；训练计划、进度、提案和确认点可返回结构化卡片。

## 非目标

- 不让模型直接读写数据库。
- 不把既有训练算法复制到 Agent 层。
- 不在第一版开放无确认的真实写操作。
- 不将 Agent 表述为医疗诊断或治疗工具。
