## 界面修复跟踪

### UI-01：自定义动作单行输入框文字显示不完整

- 状态：本地修复及自动化验证完成；2026-09-08 用户反馈真机复验通过。
- 页面：编辑训练计划 → 我的自定义动作。
- 证据：用户提供真机截图 `codex-clipboard-9ac9e8bb-3a8c-4968-b790-e79b05fe950f.jpg`。
- 用户描述：输入框太窄，无法看见输入文字。
- 截图表现：动作名称、训练部位、已知禁忌的单行输入区高度较小，文字在垂直方向被裁切；动作方法多行输入区未见同样裁切。
- 代码检查与修复：共享输入样式没有明确高度，却设置上下内边距。为三个单行输入设置统一高度、行高、全宽和防收缩，去掉上下内边距；不改变输入处理、安全说明或提交逻辑。
- 本次范围：上述单行输入的可见高度、字体与内边距，以及个性化计划页面的共享自定义动作入口；未知安全信息允许添加、仅显示约定小字的行为保持不变。
- 复验清单：输入文字、占位文字和光标完整可见，长文本可正常编辑；系统字体大小、键盘弹出和两处入口。用户对修复整体反馈通过，未单独提供各设备与字体组合执行结果。

### UI-02：归档计划删除按钮文案、位置与尺寸

- 状态：本地修复及自动化验证完成；2026-09-08 用户反馈真机复验通过，包含后续同款标签框、对齐及红色配色调整。
- 页面：训练页 → 已归档计划卡片。
- 证据：用户提供真机截图 `codex-clipboard-44e5a71f-8c86-47a3-b407-09d1257ae3ef.jpg`。
- 用户指定：将“删除归档计划”改为“删除”，放在卡片顶部“已归档”标签左侧临近处；按钮外框贴合文字，去掉当前大块空白。
- 已实现：移除通用大按钮样式，“删除”使用紧凑文字标签，透明外围保留点击区域，与“已归档”同组相邻；长标题可换行。两者共用相同标签框圆角、内边距、高度与文字度量，上下边缘对齐；按用户最新要求，删除配色复用“删除计划”的红字、浅红底框，归档标签保持灰色。原有页内确认、取消及失败重试保持不变。
- 复验清单：删除按钮与已归档标签相邻、紧凑对齐；长计划名与窄屏下不重叠或挤压。保留可用点击区域，不因视觉缩小使触控困难。
- 行为保持：仍使用原有确认与列表隐藏流程，保留训练历史和审计，不因 UI 调整改成无确认删除或物理删除。
