“来源匹配”以表中的具体品种、去皮状态和加工方式为条件。例如草虾仁不能泛称所有虾，黄鳍金枪鱼不能代表蓝鳍鱼腩，生开心果仁不能代表盐焗烤开心果。品种限定属于原候选要求的精确化；仍须在真实入库前确认最终显示名称与可见说明。来源数据代表其样品／参考定义，不是对用户手中食品的精密测量。

## 已解决的生熟重点

土豆（去皮，生）、土豆（去皮，蒸熟）、紫薯（去皮，生）、紫薯（去皮，蒸熟）均有独立来源。熟制确实为蒸制，不用水煮替代；紫薯确实为紫肉甘薯，不拿红薯改名。

生土豆与蒸土豆使用不同来源样品，因此不能拿二者营养差异当作同一批食材的烹调损耗。生、熟称重方式不同；蒸熟紫薯每 100g 能量略低于生品也不意味着蒸制具有固定减热量效果。数据库废弃率不是为用户自动去骨／去皮的精确换算率。

## 数据质量检查及边界

- 66 个候选 ID 唯一且与候选表逐项对应。61 项有供审查的同源四大字段，另5项没有采纳任何营养数字；其中61不等于可放行数量。
- 305 个字段位置已检查（包括可空纤维）；8 项纤维缺失维持 null，来源明确的零保留零。未把缺失、Tr、空白转零。
- MEXT 鲫鱼纤维原文为 `(0)`，原始标记保留；USDA 保留分析、计算、估算零等来源代码。不能把参考表中全部数字标为“实测”。
- 黄瓜与小白菜的4/4/9结果比源能量高约20%以上，但绝对差约3–4kcal/100g；低能量食物分母小，来源能量口径也不同。这是复核提示，不足以自动判错或修改源值。
- TFDA 同时存在“熱量”与“修正熱量”；当前报告选择前者且保留后者，避免混搭。真实导入时需把所用字段固定在目录说明，不能择低或用4/4/9覆盖。
- 来源档案的两个 SHA256 已重新检查。字段检查从原始TFDA行、USDA原始记录完成，并拒绝重复字段／非法单位／负值／非有限数。
- MEXT 五项网页数据完成原字段读回核对，但本地 HTML 下载 TLS 失败，因此无网页档案哈希；链接、版本、转录字段与原标记均保留。没有将转录写成自动抓取。
- 未声称对生产数据库进行盘点，也未核定旧21项的原始出处。本次不更正旧食品，不重算历史餐次，不覆盖草稿，不改变Agent流程。
