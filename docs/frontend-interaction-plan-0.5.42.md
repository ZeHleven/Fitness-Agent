## 统一交互规则

### 触感与节奏

- 可点击按钮按下时轻微缩放和变色；命中范围、布局尺寸与文字宽度保持稳定。
- 按压反馈初值 100ms、状态过渡 180ms、新内容进场 240ms；这些仅为设计参数，不是性能测量或平台保证。
- 以单次、小幅位移与透明度变化为主；只为新内容进场，不每次渲染重播。
- 成功反馈先更新真实状态，再短暂强调该状态；不增加强制等待时间。重要错误及操作结果不能仅靠颜色或动画表达。
- 动画只表现状态，不能提交请求、决定业务成功、启动真实计时或触发重试。

### 停止、打断与降级

- 触摸取消、移出有效目标和页面隐藏时，撤销按压视觉；不能将取消手势解释成提交。
- 动效进行中有新状态时，以最新状态为准，从当前视觉状态收尾，不排队回放旧状态。
- 用户开始滚动、触摸输入或切换编辑对象时，撤销尚未发生的旧自动定位；已开始滚动的中断能力需在微信真机核对，不假定网页行为相同。
- 页面隐藏或销毁后清理装饰定时器、监听和过渡状态。返回直接呈现当前状态，不补播成功动画或过期引导。
- 停止休息进度条的过渡不停止真实休息计时；停止 Agent 加载动效不取消后台任务。
- 按用户最新要求，正常显示轻量动效，不提供“减少动态效果”卡片、开关或本机设置；旧试做版设置不再读取，不要求用户清除缓存。
- 页面隐藏/销毁仍立即清理动效，业务失败仍静态显示错误；删除开关不代表动画必须持续运行。
- 保留宿主支持时的自动 CSS 无障碍兼容，无需用户在小程序内设置，不声称所有微信版本自动跟随系统。动画不支持时信息、计时和操作仍须完整。

## 三个场景的状态契约

| 场景与触发 | 视觉反馈 | 结束或打断 | 必须保持的业务行为 |
| --- | --- | --- | --- |
| 训练：点击保存一组 | 按钮轻压，原位置显示保存中；成功后该行显示已保存并短暂强调 | 失败立即显示错误；用户修改输入后旧成功强调不得覆盖新输入 | 沿用提交锁；不重复写组；结果未知不显示成功 |
| 训练：保存后进入休息 | 休息面板轻量进场，倒计时及进度取现有时间戳 | 返回页面不重播；动画不支持时静态可用；目标时间到达后只更新说明 | 不等待进场结束才开始计时；目标时间到不自动结束或保存真实休息 |
| 训练：结束休息 | 先显示正在保存，成功后面板轻量退场 | 保存失败保留面板和原结束时间；退场期间不响应旧按钮 | 不改变真实组间休息秒数，不因视觉取消丢失待保存事件 |
| 饮食：添加标准/私人食品 | 立即更新草稿，再定位编辑区，突出新加入项，说明“已加入本餐，尚未保存” | 用户开始操作时停止旧定位；连续添加不排队滚动；新行只进场一次 | 只修改草稿；创建私人食品与保存餐次仍是不同业务动作 |
| 饮食：营养数字或餐次保存 | 汇总变化时轻量淡入，不从零翻滚；保存按钮稳定显示处理中 | 保存成功后正常关闭编辑区并提示；失败保留原输入 | 空白不变成零；不因动效重建 Input 或改变 key；未知结果先核对、不自动重放 POST |
| Agent：新回答/提案到达 | 仅新消息轻量进场，完整正文立即可读；加载状态反映现有真实阶段 | 历史恢复不重播；离页取消装饰监听；阅读旧内容时不抢滚动位置 | 不改变 run_id、client_request_id、请求恢复及会话隔离 |
| Agent：阅读历史时有新消息 | 保持阅读位置，提供轻量“查看新消息”入口；用户点击后再定位 | 用户主动触底后恢复跟随；动画不支持时仍可定位 | 初次打开会话仍可定位最新消息；迟到响应不得进入另一会话 |
| 通用提案：展开页内确认/取消/执行 | 确认区轻量出现，取消后收起；执行中显示真实状态，终态稳定展示 | 取消/离页立即清除授权目标，视觉退场残影不可点击 | 审阅、二次确认、版本、指纹、过期、执行锁及结果核对全部保留 |

## 卡片层次

- 主操作卡片：保持白底、现有圆角和轻阴影；让用户容易找到当前操作。
- 卡片内食品行、训练组等：用浅底、细分隔和留白组织，不给每一层都加阴影。
- 辅助说明：保持较低视觉权重，但可读性、字体放大和安全提示不可降低。
- 进行中的休息面板、确认区在需要时突出，结束后恢复稳定层级；不覆盖键盘、主要按钮或正文。
- 不用压缩行高、裁切容器、重新挂载输入框来实现动画；保留曾修复的文字完整显示。

## 实施顺序

1. 基线保护：核对最新干净 main，隔离分支开发，读取项目约束并保存 0.5.41 可比基线。
2. 补行为测试：请求挂起/成功/失败/未知、触摸取消、连续点击、离页返回及过期回调，先覆盖业务不变量；旧动效设置不得影响当前正常动效。
3. 在现有小程序中制作限定范围的交互试做版：统一按钮与动效生命周期、训练保存与休息。按最新反馈移除训练进行中及首页的重复提前结束入口，统一通过“继续 → 完成训练”；空训练沿用“放弃”。保留历史记录展示，不改后端提前结束接口。不给生产导入目录打补丁。
4. 复用同一交互规范接入饮食及 Agent；不扩大到所有页面，不在试做中增加后端接口。
5. 自动化通过后生成隔离测试包，由用户在真机查看手感、输入和打断行为，再调节时长/幅度。
6. 全部验收通过后，经用户授权再提交、推送、创建 PR；标准 Project CI 全绿后合并并从干净 main 构建正式小程序。后端无需重新部署。

## 验证与放行条件

- 复用实际页面运行时测试，不以源码包含某段样式代替交互测试；动画结束事件缺失时业务仍正确。
- 训练：连续点击只写一次；动画中切后台仍按真实时间恢复；结束休息失败保留原结束时刻；移除重复入口不改变正常完成流程或历史记录。
- 饮食：100→清空→150g、连续添加、删除前一项、长食品名、切换编辑、保存失败/未知、后台恢复；草稿、焦点与键盘不能因动效丢失或被裁切。
- Agent：历史不重播、上滑阅读不被拉走、用户点击新消息入口正确定位；断网/超时/恢复、会话切换及迟到响应不重复提交、不串会话。
- 提案：未审阅零执行、取消零执行、离页后旧确认失效、连续确认只执行一次；视觉变化不能绕过业务保护。
- 无动效开关：“我的”正常或加载失败时均不显示开关；旧设置值存在也不影响动效，不写个人资料或清除其他缓存。
- 运行全部小程序行为/Proposal 契约测试、类型检查、生产构建和全包 JS 语法兼容门禁；发布前运行完整标准 Project CI。
- 同机同数据对比 0.5.41 与测试版：页面可操作时间、点击反馈、请求数量、包体及可获得的帧耗时/卡顿记录。不得以模拟器观感宣称真机稳定 60fps。
- 真机覆盖正常网络、慢网、断网恢复、小屏、大字体、键盘遮挡及后台返回。不能为了动画增加业务请求、阻塞输入或延迟提交。
- 如某项效果在真机不稳定，优先关闭该项装饰效果、保留完整静态反馈，不放宽数据安全或功能验收要求。
