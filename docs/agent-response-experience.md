## 范围与实现

- 小程序仅对 assistant 消息使用安全的轻量文本渲染：标题、加粗、列表、段落、行内及围栏代码。用户输入不格式化；新回复、恢复中的回复及历史消息共用组件。服务端原文不改写。
- 只使用 Taro Text/View；HTML、链接、图片语法不产生可执行节点、外部导航或自动网络请求。不支持的语法按文本展示，不是完整 Markdown 引擎。
- 未闭合符号、`C#`、`3 * 8`、`2**3`、小数和单位保留。超过 32000 字符、400 行或 2000 文本片段的内容退回完整纯文本，不静默截断；React.memo 避免输入及轮询时反复解析不变的历史。
- direct answer 和 planned finalizer 共用表达规则：回应当前问题、短句、适量分段，不每次复述能力，不以道歉或假想事实填补上下文。未知动作保留不确定性；感谢可以自然结束。
- 更新欢迎语、缺信息、理解失败、提案待确认、无可处理提案、否定/不明确授权及未持久化提案的固定兜底文案。只改变呈现；错误码、终态、确认权限和持久化规则不变。
- 表达优化本身没有修改意图模型、语义路由、工具授权、健康拦截、Proposal 确认、食品生成或数据库结构；没有额外的模型“润色”调用。随后经用户授权补修了下面两处确定性校验误判，未改变意图模型或写入权限。

提示词改动与评测安排参考了 [Prompt engineering](https://developers.openai.com/api/docs/guides/prompt-engineering) 和 [Evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices)：保留原有业务约束，用典型、边缘、对抗、多轮样本检验输出。不是模型迁移。

## 两处边界补修（2026-09-10，用户单独授权）

1. `记录里 3 * 8、1.5 kg、C# 这些符号分别是啥？`：真实路由两次触发 `semantic_mutation_structure_missing`。服务端安全停止，没读写业务数据，但未回答正常的符号解释问题。新的表达提示词不参与这一层，不能靠展示层修好。
2. `“确认这个提案”这句话是什么意思？我没让你执行。`：模型可以给出解释，但部分措辞会触发现有“未持久化提案”保护，使解释被安全兜底替换。实际接口没有写入；这与“这个提案先别执行”被正确保留原状态不是同一问题。

以上是补修前的复现结果，不是当前状态。本轮已实施：

- 在旧的一致性校验中识别 `记录` 的方位/定语名词用法，不再把 `记录里`、`记录中的`、`记录的单位` 当成记录命令。只去掉这处词法证据，不改写用户消息，不指定工具，不跳过模型。`记录体重`、`记录中午的饮食`、`记录里程` 仍作为动词处理；同句中其他实际修改命令仍保留。
- 未持久化提案保护改为检查当前状态断言和实际确认邀请。引用中的示例、同一分句内的定义、`待确认` 状态词及 `确认后` 条件不再被机械拼接为邀请；定义后另起分句的“已生成提案”、第一人称/“为你”断言、实际确认邀请仍被拦截。未生成应有提案及 `terminal_action=proposal` 仍强制安全降级。
- 不新增解释语句白名单，不新增模型调用，不修改 `parse_explicit_proposal_decision`、通用确认/拒绝、所有权、健康或版本校验。
