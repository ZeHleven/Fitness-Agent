# 0.5.39 Agent 只读请求否定误判修复

日期：2026-09-09。基于已合并 `main` 的 `2f3f9105ce59d5fb2d2c9916ea921b7e6db1363e`，本地分支 `codex/agent-read-negation-fix`。

## 现场与根因

正式后端 0.5.38 部署后，用户发送“查看我当前的训练计划，只查看，不修改。”，收到意图理解不可用提示。云端日志两次返回 `semantic_mutation_structure_missing`，读取工具授权数量为 0。本地注入正确的 query/read 模型结果，也能稳定复现两次相同错误。

旧否定模式识别“不要／不用／先别”等前缀，却漏掉与动词相邻的“不”。因此规则把“不修改”错误归类为 mutation；语义一致性检查随后拒绝模型的非修改判断。另一个既有问题是，任意一处已识别的否定都会取消整句 mutation，例如“不要修改周二，把周三的休息改为180秒”。

这不是日志所示的模型超时。没有读取到计划不代表计划不存在或已丢失；该失败分支没有运行计划业务工具，仍会保存会话和运行审计记录。

## 修复范围

- 仅调整 `agent_intent.py` 的既有否定识别与候选命令判断，不新增只读接口旁路或固定问句白名单。
- 识别相邻的“不修改／不删除”等否定，允许词间空格；否定范围不跨逗号、句号、分号或换行等边界。
- 排除被否定的动词及紧邻并列动词，保留另一处肯定修改请求，不再用一个否定取消整句操作。
- 保留“不得不／不能不／不是不”等已覆盖双重否定的修改候选；并非声称已解决所有中文否定表达。
- 查看历史“记录”等名词的判断使用同一份排除否定后的候选文本，避免负面限制被重新当成写入证据。
- 模型仍负责普通语义理解；未配置、关闭或超时时，不因这次修复直接放行读取。原始消息仍原样传给模型，不将用于规则检查的文本作为用户授权。
- 未删除或放宽 `semantic_mutation_structure_missing` 一致性检查。明确修改被模型降为查询时，仍修复重试或安全停止。
- 未改提案确认／拒绝识别、运行时原始消息校验、业务写入、所有权、健康、版本、过期或幂等保护；未改模型、提示词、API、数据库或小程序。
