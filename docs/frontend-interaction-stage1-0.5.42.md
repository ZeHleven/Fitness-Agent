## 已实现

1. 共用 `FeedbackButton` 保持原生按钮命中区域和原布局。按钮标签短暂轻压；等待真实保存时原位显示“保存中”，同步锁阻止同一行连续提交。
2. 训练组保存成功才显示“已保存”与短暂浅色强调。失败、结果未知不播放成功；保存期间用户继续修改输入时，保留新输入，不把它误标为已保存。
3. 休息面板按真实保存结果进场；成功结束休息后立即移除可操作面板，只保留不响应操作的短暂退场提示。没有请求或业务状态依赖动画完成事件。
4. 组保存、组间休息的时间戳及失败重试沿用现有逻辑。页面隐藏时停止本地更新/装饰定时器，返回按时间戳恢复，不补播旧成功反馈，后台迟到的新纪录提示也不补弹。
5. 根据用户最新反馈，移除“我的”本机动效开关、卡片、相关样式及偏好模块。保留正常动效和生命周期清理；旧 `fitness_reduce_motion_v1` 值不再读取，不用清缓存。保留宿主支持时的自动 CSS 无障碍兼容，不增加界面设置，不声称所有微信版本自动跟随系统。
6. 移除训练进行中页面的“保留记录并提前结束”按钮、二次选择区和调用处理器；r3 同时移除首页“保留记录并结束旧训练”及整块恢复卡片、关联状态/处理器/样式。首页仅保留“继续”卡片：需要继续则进入记录，需要结束则在训练页点击“完成训练”。空训练仍不能伪装成完成，可通过原有“放弃”退出。
7. 保留后端接口及 `ended_early` 历史详情。原计划已删除时的说明改为当前页“完成训练”，不再指向已移除的首页入口。只读核对完成接口及两处自适应服务：无原计划时跳过调整提案，已有有效训练组仍能完成并保留；没有放宽至少一组、归属、反馈或 Proposal 校验。本轮未运行后端数据库测试，也未修改后端或数据库。

按钮初始按压参数为 100ms，状态反馈 180ms，休息进场 240ms，保存强调 600ms；只是设计参数，不是延迟测量。业务操作与真实计时不依赖动画。

### 真机分组

1. 按钮和保存：开启训练，用测试组保存；确认按压反馈轻、按钮位置不跳、保存中不重复提交、成功后“已保存”和短暂行反馈；失败保留输入，未核对结果不能显示成功。
2. 休息：保存后面板出现且计时不等动画；提前结束休息后记录正确且旧按钮不可再点击；断网后重试保留最初结束时刻。
3. 后台和打断：休息中切后台约 15 秒再回，倒计时按经过时间恢复、不重播进场；快速离开/返回不补弹旧成功提示。按下后取消/滑出按钮不应触发保存（原生真机验证项）。
4. r3 界面精简：首页只有可用的“继续”卡片，不再出现“保留记录并结束旧训练”或空白卡片。点“继续”后可记录并完成训练；空记录保留“放弃”。“我的”无动效开关，训练进行中无提前结束入口。快速复测保存一组、结束休息和返回恢复；不要将已撤回的动效开关验收记为通过。
5. 小屏、大字体、键盘：重量/次数文字完整、输入不中断、反馈不改变命中区域；确认面板不新增遮挡。记录正常/慢网下手感问题，必要时缩小或关闭装饰效果。
