- 明确选择 `resistance_training`（普通抗阻）或 `bodyweight_resistance`（普通自重抗阻）。创建时可留空；不使用名称、器械或自定义动作默认“力量”字段猜测分类。

- 没有增加有氧／HIIT、动作搜索、运动库扩充、自动分类、整场兜底或删除训练记录。

## 数据与接口

`0029_exercise_energy_classification.py` 接在 `0028` 之后：

- `Exercise.energy_category`、`energy_category_version`。
- `SessionExercise.energy_category`、`energy_category_source`、`energy_rule_version`。
- `WorkoutSession.energy_classification_version`。
- 分类列有数据库枚举检查。旧标准动作按原有映射冻结快照，旧自定义保持未分类。用户分类版本变化、用户快照或历史修订存在时拒绝降级丢弃数据。
- 自动开始训练、手动记录训练均保存快照；修改库分类不回写已开始或已结束训练。

所有路径位于 `/api/v1`：

- `POST /exercises/custom` 增加可选 `energy_category`；`GET /exercises/custom` 返回分类和库版本。
- `PUT /exercises/custom/{id}/energy-category`：`{energy_category, expected_version}`。仅本人启用的自定义动作，影响今后开始的训练。重复相同定义的创建保持既有幂等行为；显式分类与已有定义冲突时提示使用编辑入口，不静默覆盖。
- `PUT /workouts/sessions/{id}/energy-classifications`：

```json
{
  "expected_version": 0,
  "update_future": false,
  "exercises": [
    {
      "session_exercise_id": "本次训练动作记录 ID",
      "energy_category": "resistance_training"
    }
  ]
}
```

同步今后分类时，所选每项还须携带 `expected_exercise_version`。仅已结束训练、有有效组、属于本人的自定义动作可修改；停用动作允许仅修订本次，不允许同步库。用户级训练锁在先，训练与动作行锁在后，整批校验后原子保存。标准动作、跨会话引用、跨用户、重复记录 ID、冲突库版本均拒绝。过时重复请求返回 409，不重复增加修订版本。

训练详情返回快照、修订号及本次／库编辑权限。今日能量增加训练实际时间、计划名称、动作名称、结构化 `reason_code`，版本 `daily_energy_v2`；不逐动作查询，不按当前计划过滤历史。

## 小程序

- 共享自定义动作组件支持新建时选择分类；“修改估算分类”区域只修改未来库分类，不添加计划动作。
- 训练详情增加批量补充／更正表单，默认仅本次，今后同步默认未勾选；保存失败保留选择。
- 同一表单只允许一个保存流程。响应丢失先 GET 核对分类、修订及必要库版本；未知状态阻止重复 PUT，提供“读取核对保存结果”。版本冲突读取后保留草稿，需用户核对并再次显式保存。
- 饮食部分估算显示“已估算消耗”；具体记录可“补充分类”或“查看训练”。计时异常不引导用户以分类修复。返回页面会重新读取今日数据，但不替换餐次草稿。
